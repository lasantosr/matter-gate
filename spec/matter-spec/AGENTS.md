# AGENTS.md (`matter-spec`)

Additive to root [`AGENTS.md`](../../AGENTS.md).

## 0. Invariants (CRITICAL)

1. **One version, one cargo process, always `--jobs 1`.** Never compile or test multiple specification versions concurrently, and never run parallel `cargo` invocations against this crate. Use `just spec-clippy [version]` and `just spec-test [version]` (or `-all` sequentially).
2. **Excluded from `default-members`.** Never add this crate to workspace `default-members`, and keep the low-memory `[profile.*.package.matter-spec]` settings in root `Cargo.toml`.
3. **Never touch autogenerated code.** `src/v*_*/`, `src/__shared/`, `src/lib.rs`, `build.rs`, and the `[features]` table in `Cargo.toml` are autogenerated; modify [`matter-spec-gen`](../matter-spec-gen/AGENTS.md) and [`xtask codegen-spec`](../../xtask/src/commands/codegen_spec/AGENTS.md) instead.
4. **Keep `#![no_std]` + `alloc`.** Keep `registry` and `serde` `no_std` + `alloc` compatible; never pull `std`-only crates into `no_std` feature paths, and never emit a `latest` version alias.

## 1. Identity

- **Crate:** `matter-spec` (`spec/matter-spec`), publishable library, excluded from `default-members`.
- **Role:** generated, version-gated Matter cluster and endpoint models, thin wire envelopes, zero-alloc conformance validation, and unit/mode extensions.

## 2. Design & Constraints

- **Exhaustive domain vs. boundary-only `#[non_exhaustive]`:** Specification enums, commands, responses, events, and conformance error enums omit `#[non_exhaustive]` so callers match exhaustively. Only cross-cluster `dispatch` enums are `#[non_exhaustive]` with an `Unknown(...)` fallback and boxed large variants (`> 64B`).
- **Option-A models & zero-clone ownership:** Spec-optional fields flatten onto records as `Optional<T>`. Owned `TryFrom` and `into_attributes` move `String`/`Bytes`/`Vec` via non-generic kernels (no `TryFrom<&AttributeValue>` on non-`Copy` generated structs).
- **Integer decoding & validation modes:** Generated `matter-spec` `TryFrom` conversions and `GlobalAttributes` use `Fit` integer decoding (matching `matter-data-model` IDs: any same-signedness `AttributeValue` integer that fits in range, `ConstraintError` on overflow, `InvalidDataType` on wrong signedness/type), while `matter-data-model` primitive `TryFrom` (`u8`..`i64`) remains strict. `RegistryValidator` defaults to `IntegerMode::Widening` (CSA TLV minimal-width rule) and can be configured to `Strict` or `Fit` via `with_integer_mode`.
- **Strict `MatterStatus` mapping:** Return `InvalidDataType` (`0x8D`) on wrong wire tags, `InvalidCommand` (`0x85`) on missing mandatory command fields, and `ConstraintError` (`0x87`) on bounds/length/enum/duplicate/unknown-field errors and missing mandatory cluster/struct/event fields.
- **Visibility & feature hygiene:** Keep `__shared` private with `pub(crate)` buckets (`unreachable_pub` stays strict) and keep internal helpers `pub(crate)`. `default = ["std"]`; `registry` and `dispatch` are opt-in; `schemars` enables `std` + `registry`.
- **Zero-alloc, non-mutating validation:** Validation runs over immutable `static`/`const` version-agnostic `SpecRegistry` descriptors without heap allocation or mutating valid inputs.
- **MSRV:** `matter-data-model` and `matter-spec` target `rust-version = "1.88"` (avoid post-1.88 syntax).

## 3. Architecture

- Re-exports `matter-data-model` at the crate root as `model`.
- Hand-written modules provide core traits, wire envelopes, error types, static conformance validation, unit/address/time newtypes, mode extensions, and runtime dispatch/JSON wrappers.
- Generated modules provide `__shared` (deduplicated cluster/global buckets) and versioned `v<major>_<minor>` trees (`globals`, `clusters`, `endpoints`, and feature-gated `dispatch` / `registry`).
- Feature tiers cascade from `all` → product domain bundles → `endpoint-<name>`, plus `unattached-clusters` (included in `all`) and `testing`, with `build.rs` emitting `cluster_<name>` `rustc-cfg` flags (also individually selectable via `MATTER_SPEC_CLUSTER_<NAME>` env vars).
